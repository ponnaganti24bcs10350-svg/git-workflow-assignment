Git Commands Reference - Personal Notes
----------------------------------------

Below are the commands I ran during this assignment, along with what each one actually does in my own words.

1. git init -b main
   I used this at the very beginning to turn my project folder into a Git-tracked repository.
   The -b main part told Git to name the starting branch "main" right away instead of the
   old default name. Without this step, Git wouldn't know anything about my files at all.

2. git status
   I ran this constantly just to see what was going on - which files Git was watching, which
   ones had changes Git hadn't saved yet, and which were completely new and unknown to Git.
   It's basically a quick sanity check before doing anything else.

3. git add index.html about.html
   This picked up my two HTML files and moved them into a holding area (called the index or
   staging area) so they'd be ready to include in my next commit. Only staged files get saved
   when you commit, so this step is essential.

4. git commit -m "Initial commit: Add index.html and about.html"
   This actually saved the staged snapshot permanently into the project history. The message
   after -m is a short note so I (or anyone else) can tell at a glance what changed in this
   particular save point.

5. git branch feature
   This made a new branch called "feature" that starts off at the exact same point as main.
   I didn't jump into it yet - I just created it. Think of it like making a copy of the
   project where I can experiment freely without touching main.

6. git checkout feature
   This switched me over to the feature branch. Any changes I make from this point forward
   go onto feature, not main, so my working version stays safe.

7. git merge --no-ff feature -m "Merge branch 'feature' into main"
   After finishing my changes on feature, I went back to main and ran this to bring those
   changes in. The --no-ff flag forces Git to record a real merge commit rather than just
   fast-forwarding, which keeps the branch history visible in the log.

8. git log --graph --oneline --decorate --all
   This prints out the whole commit history as a text diagram showing all branches. It's
   really useful for confirming that my branch structure and merges look the way I expected.

9. git status --ignored
   Similar to plain git status but also reveals files that are being intentionally skipped
   because of rules in the .gitignore file. I used this to confirm my .log files and temp/
   folder were actually being filtered out.

10. git reset --soft HEAD~1
    This undid my last commit but kept all the file changes staged - nothing was deleted.
    It's like telling Git "pretend that last commit didn't happen, but keep the work".
    Useful when I realised I'd committed something too early or by mistake.

11. git remote add origin https://github.com/ponnaganti24bcs10350-svg/git-workflow-assignment.git
    This told my local Git where the GitHub repository lives by giving it a nickname "origin".
    Without this, there's no connection between my local project and GitHub at all.

12. git remote -v
    A quick check to confirm the remote URL got saved correctly - prints both the fetch and
    push addresses so I can see at a glance that origin is pointing to the right place.

13. git push -u origin main
    This sent all my local main branch commits up to GitHub for the first time. The -u flag
    links my local main to the remote one, so future push/pull commands know where to go
    without me specifying every time.

14. git push origin feature
    Same idea but for the feature branch - this made sure the full branch history including
    my feature commits was visible on GitHub too, not just the merged result on main.
